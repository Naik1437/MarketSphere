# Vercel Hobby deployment

The repository root `vercel.json` defines three Vercel Services: the Next.js
frontend, the Express API, and the internal FastAPI engine. `/api/*` is routed
to Express; the API receives an internal `PYTHON_ENGINE_URL` binding for the
FastAPI service. Docker Compose remains the supported local/worker runtime.

## Required Vercel environment variables

Set these in Vercel for Production, Preview, and Development as appropriate:

```text
NODE_ENV=production
DATABASE_URL=<Neon pooled or direct postgresql URL with sslmode=require>
REDIS_URL=<Upstash rediss:// URL including password>
JWT_ACCESS_SECRET=<random secret, at least 16 characters>
JWT_REFRESH_SECRET=<random secret, at least 16 characters>
WEBHOOK_SIGNING_SECRET=<random secret, at least 16 characters>
CORS_ORIGIN=<the Vercel deployment origin>
NEXT_PUBLIC_API_URL=<leave unset for same-origin routing, or set to the deployment origin>
```

The `PYTHON_ENGINE_URL` value is generated by the service binding and must not
be hardcoded. Do not commit provider credentials. Existing optional Stripe,
shipping, email, and storage variables are only set when a real sandbox
account is available; otherwise the existing simulation mode remains active.

## Migration and deployment

Use the Neon direct (unpooled) URL for migrations, then the pooled URL for
runtime if the Neon project provides both:

```powershell
$env:DATABASE_URL="<Neon direct URL with sslmode=require>"
npm ci --prefix apps/api
npx --prefix apps/api prisma generate
npx --prefix apps/api prisma migrate deploy
```

Connect the repository to Vercel, select the repository root, and deploy after
the required environment variables are configured. Verify `/`, `/api/health`,
and the API authenticated flows after deployment. This document does not claim
that a deployment or provider account has been created.

## Worker and free-tier boundary

`apps/api/src/worker.ts` is a long-running BullMQ consumer and remains in the
Docker Compose worker service. It is not deployed as a Vercel Function or
Daemon: Vercel Hobby request functions are not a durable always-on worker
replacement. A separate always-on worker host or queue service would require
an external provider decision; no paid resource is activated here.

Neon, Upstash, and any provider sandbox account must be created and verified by
the user. Free-tier availability, quotas, account verification, HTTPS domain
setup, backups, and rollback are external deployment checks.
